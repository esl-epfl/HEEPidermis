# Register index

This is a flat, human-readable index of **every register of the HEEPidermis external (analog front-end and decimation) peripherals**, with the information needed to drive the cheep from an external controller (e.g. an Arduino) through the SPI slave:

- Peripheral / subsystem the register belongs to
- Descriptive name
- Alias: the code-like name used to build the C `#define`s (identical to the names in the generated `*_regs.h` headers)
- **Full 32-bit address** in the SoC memory map (no offset arithmetic needed — ready to paste into an Arduino sketch)
- Field position / number of bits, and the values it can take
- Reset (default) value
- Description and comments

## Where this information comes from

X-HEEP's automatic documentation flow cannot be reused here: the register-to-address mapping depends on configuration data that in this project lives in *our* configuration file, not in the peripheral itself. These tables were therefore derived by hand from three sources:

| Source | What it provides |
| :-- | :-- |
| [`config/cheep_configs.hjson`](../../config/cheep_configs.hjson) (`ext_periph` and `ao_peripherals` sections) | The **offset of each peripheral** inside the external-peripheral region |
| [`hw/vendor/x-heep/sw/device/lib/runtime/core_v_mini_mcu.h`](../../hw/vendor/x-heep/sw/device/lib/runtime/core_v_mini_mcu.h) | The **base addresses** of the memory-map regions (`AO_PERIPHERAL_START_ADDRESS`, `EXT_PERIPHERAL_START_ADDRESS`, RAM banks, ...) |
| `hw/ip/cheep-peripherals/<periph>/data/<periph>.hjson` (regtool hjson) and the generated `sw/external/lib/drivers/<periph>/<periph>_regs.h` | Register names, field positions, widths, access rights and reset values |

The computation of any register address is:

```text
register address = EXT_PERIPHERAL_START_ADDRESS     (0x2000_0000, always-on domain)
                 + 0x0007_0000                      (ext_peripheral slot in ao_peripherals)
                 + <peripheral offset>              (from config/cheep_configs.hjson)
                 + <register offset>                (from the hjson / *_regs.h)
```

> ⚠️ If you move a peripheral in `config/cheep_configs.hjson` or edit its hjson, this document must be regenerated by hand. The final addresses are also available (as C macros that compute them at compile time) in the generated [`sw/external/lib/runtime/cheep.h`](../../sw/external/lib/runtime/cheep.h).

### Program and data addresses (linker)

These come from the `linker_sections` block of [`config/cheep_configs.hjson`](../../config/cheep_configs.hjson) and are rendered into the linker script (`sw/linker/link.ld.tpl`). **They can change if the configuration or the linker script changes**, so re-check them before hard-coding them in an external tool.

| Item | Address | Comment |
| :-- | :-- | :-- |
| Interrupt vector table (`.vectors`) | `0x0000_0000` | Start of SRAM0 |
| **Boot / entry address** (`__boot_address`) | `0x0000_0180` | crt0 `.init` section, where the CPU starts fetching |
| **Start of the program** (code section, ram0) | `0x0000_0000` | `.vectors`, `.init`, `.text`, plus all program-owned runtime data |
| **Start of the data** (data section, ram1) | `0x0000_4000` | `.rodata`, `.data`, `.bss`, then heap and stack (each `0x800` by default) |
| Debug word (`.debug_mem`, ram2) | `0x0000_3FFC` | 4-byte mailbox used by the testbench/boot flow |

> With the `link_flash_exec` boot mode the program is linked into the external flash instead, i.e. code at `0x4000_0000`. The addresses above correspond to the default `link.ld` (RAM-execution) flow, which is the one used when loading a program through the SPI slave.

## Using these addresses over the SPI slave

The SPI slave is purely an interface to the outside world (it cannot be commanded from the on-chip firmware): an external master — e.g. an Arduino — drives `CS`, `SCK` and `MOSI` to read/write **any 32-bit word of the SoC memory map, using exactly the full addresses listed above**. The wire format is (full details in the [X-HEEP SPI slave documentation](../../hw/vendor/x-heep/docs/source/Peripherals/SPI_slave.md)):

1. Pull `CS` low and start toggling `SCK`; send everything back-to-back, with no idle SCK cycle between commands.
2. *(Optional)* Set the dummy cycles: 2-byte command `DUMMY_CYCLES, 0x11` (default 32 cycles).
3. Set the wrap length L (number of 32-bit words of the burst): one word with `L[15:8], 0x30, L[7:0], 0x20`.
4. Direction: `0x2` = write, `0xB` = read.
5. Address: the 32-bit address above, **little-endian** (LSB first in time).
6. Data: for writes, send the 32-bit words little-endian; for reads, keep toggling `SCK` for the dummy cycles and sample `MISO`.

Remember that all multi-byte fields (address and data) are transferred little-endian, and that the slave always works on whole 32-bit words.
